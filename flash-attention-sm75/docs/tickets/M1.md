## CUTLASS workaround

The patch attempt first failed because `setup.py:316` invokes
`git submodule update --init csrc/cutlass`, and the comfyui
container has no usable network to github.com (the slow link
cannot fetch a multi-GB repo in reasonable time).

**Workaround:** the workstation host had a pre-existing CUTLASS
checkout at `/opt/flash-attention-turing/csrc/cutlass/` (from a
prior failed `comfyui-turing` attempt). This CUTLASS was copied
into the flash-attention clone (`cp -r ... csrc/cutlass`) before
the tar+extract step, so the `assert os.path.exists("csrc/cutlass/include/cutlass/cutlass.h")`
check in `setup.py:319` passes without needing the submodule.

This workaround is documented in the commit history. The
`scripts/apply-patch-and-install.sh` script does **not** currently
include the CUTLASS-copy step. **M1 follow-up:** update the
script to copy CUTLASS from the host (or `git clone` it on the
host where the network works) before invoking `pip install`.
