## Goal

Decide between Strategy A (new kernel from scratch) and Strategy B
(fork `Dao-AILab/flash-attention` and re-enable sm_75 in the build
matrix).

## Decision: Strategy B

**Rationale:** `csrc/flash_attn/src/kernel_traits.h:30-40` already
has the sm_75 code path via CUTLASS `SM75_16x8x8_F32F16F16F32_TN`
(m16n8k8 fp16 → fp32 mma with **fp32 accumulator**). The sm_75
path is the **opposite** of the community forks' approach
(which use `mma.sync.aligned.m8n8k8.f16.f16.f16.f16` with fp16
accumulator and pay the precision price). Only the build matrix
in `setup.py` was dropped. The patch is 5 lines.

See `docs/strategy-decision.md` for the full rationale and
`docs/upstream-analysis.md` for the file-by-file walkthrough of
how sm_75 is wired upstream.
