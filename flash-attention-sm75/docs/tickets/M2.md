## Goal

Run the unit tests from M1 and verify correctness on sm_75. The
key metric: **does the patched flash-attention produce output that
matches `F.scaled_dot_product_attention` reference on sm_75?**

This is the make-or-break test for Strategy B. If the kernel code
is correct (which we believe based on the upstream analysis), the
patch should produce correct output. If it does not, the failure
mode tells us whether to fall back to Strategy A (new kernel).

## Diagnostic

The 5 unit tests from M1 must all pass with `max_abs_diff < 0.05`
against pytorch SDPA reference. If any test fails, this is the
diagnostic:

- `max_abs_diff > 0.1` in any test: **kernel has a real bug, not
  a precision-loss issue**. Likely causes: CUTLASS mma atom
  `SM75_16x8x8_F32F16F16F32_TN` used incorrectly; `ldmatrix` for
  sm_75 used incorrectly; softmax accumulator cast to fp16
  somewhere it shouldn't be.
- `max_abs_diff ∈ [0.05, 0.1]`: precision-loss issue, not a bug.
  Investigate per-row vs per-tile scale in softmax rescale.
- All tests pass with `max_abs_diff < 0.05`: **Strategy B
  succeeds**. Proceed to M3 (ComfyUI integration).

**Qwen code review:** review test results, diagnostic chain if any
test fails, the `max_abs_diff` value for each test case. Approve
before proceeding to M3.
