## Goal

Run real workflows on RTX 2080 Ti (sm_75) with
`--use-flash-attention` and confirm correct output for both
**Qwen-Image 2.1** and **Minimax H3**.

## Steps

1. **Qwen-Image 2.1 test.** Use the existing workflow
   `/opt/comfyui/image_qwen_image_2_1_t2i_api.json`. Run it via
   the existing `comfyui_run.py` helper:
   ```bash
   python3 /tmp/comfyui_run.py /opt/comfyui/image_qwen_image_2_1_t2i_api.json --label flash-qwen --timeout 600
   ```
   **Pass criteria:** output is a recognizable image (visual
   inspection by vaskes); size > 1.5 MB; time within 1.05x of the
   140 s baseline (correctness bar, not speed bar).
2. **H3 test.** Use the existing workflow
   `/opt/comfyui/video_minimax_h3_t2v_api.json`. Run the same
   way. **Pass criteria:** output is a recognizable video, time
   within 1.05x of the 1:45 baseline.
3. **Save the Qwen output** at
   `flash-attention-sm75/tests/results/qwen_flash.png` and the
   H3 output at
   `flash-attention-sm75/tests/results/h3_flash.mp4` for review.
4. **If M4 fails** (output is gray square or purple/green dots —
   the failure modes we already documented for the existing
   community forks), the kernel code may have a bug despite the
   fp32-accumulator design. The diagnostic is the same as M2's
   diagnostic; the cause is likely in the softmax implementation,
   not the mma instruction. Investigate
   `csrc/flash_attn/src/softmax.h` (or wherever the softmax lives
   in the upstream code).

**Qwen code review:** review saved output files, the workflow
JSONs (no changes expected), the ComfyUI log showing the flash
attention path is used.
